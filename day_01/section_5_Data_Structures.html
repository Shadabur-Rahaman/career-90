The container family

Two axes decide everything.

Every method, bug, and idiom below is a consequence of where a container sits on these two axes.

Order and mutability aren't just properties — they're what each container is for. Click one to jump to its lab.

ORDERED · MUTABLE

list

Slots addressed by position. Grows, shrinks, reorders in place.

ORDERED · IMMUTABLE

tuple

Slots addressed by position, sealed at creation. The container can't change — its contents might.

UNORDERED · UNIQUE

set

No slots, no order — only membership. Duplicates are structurally impossible.

MAPPED · MUTABLE

dict

Slots addressed by key instead of position. Insertion order is remembered, but lookup ignores it.

Lab 02 — LIST AS STACK / QUEUE

Same object, opposite cost.

A list is excellent at one end and expensive at the other. This is not a style preference — it's a memory-layout fact you can watch.

A stack only ever touches the end of the list — cheap. A queue built from a plain list has to touch the front — every removal or insertion there re-shifts every remaining element. Run both and count the shifts.

STACK — LIFO, append / pop()0 shifts
O(1) — the top of a list is also its end. Nothing else moves.
QUEUE FROM A LIST — FIFO, insert(0,v) / pop(0)0 shifts
O(n) — every other element has to slide over to keep index 0 free. Each slide below is one counted shift.
the fix — collections.deque keeps pointers at both ends instead of shifting: queue.popleft() is O(1), the same cost as the stack's pop(). Same idea, no cost.
Lab 03 — LIST COMPREHENSIONS

They look like the loop. They don't scope like the loop.

Predict before you run. Most people get the second question wrong the first time — that's the point.
01 / 02 — This runs to completion. What does the last line print?
squares = []for x in range(5): squares.append(x ** 2)print(x)
prints 4
raises NameError
correct — 4. A plain for loop has no scope of its own. x is bound in the same namespace that runs the loop, so it simply keeps its last value: 4, the final item range(5) produced before the loop ended.
02 / 02 — Now the equivalent comprehension. Same question.
squares = [x ** 2 for x in range(5)]print(x)
prints 4
raises NameError

Lab 08 — THE ITERATION TRAP

Deleting from a list while walking it skips a neighbor.

This is the bug behind the doc's warning: "it is often simpler and safer to create a new list instead."

Source: raw_data = [56.2, NaN, 51.7, 55.3, 52.5, NaN, 47.8]. Goal: drop the NaNs.

APPROACH A — delete while iterating
for i, v in enumerate(raw_data): if isnan(v): del raw_data[i]
APPROACH B — build a new list
filtered = [] for v in raw_data: if not isnan(v): filtered.append(v)
