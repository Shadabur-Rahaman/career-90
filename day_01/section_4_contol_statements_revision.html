4.1

if Statements

Python's branching tool. Zero or more elif, one optional else — and once a branch runs, the rest are skipped.

SIMPLE MODEL Python checks conditions top to bottom, like a bouncer checking a line of doors. The first door that says "yes" is the one it walks through — every door after that is ignored, even if it would also say "yes."
TECHNICAL An if … elif … elif … else chain is Python's substitute for a switch/case statement — but unlike some switch statements, there is no fallthrough. Exactly one branch (or none) executes.
EXECUTION VISUALIZER 
x = 42if x < 0:    x = 0    print('Negative changed to zero')elif x == 0:    print('Zero')elif x == 1:    print('Single')else:    print('More')

WHAT'S HAPPENING
⚠ COMMON TRAP
BEGINNERS THINK"Each elif is checked independently, so if x==0 is somehow also true later, that branch runs too."
↓
PYTHON ACTUALLY DOESStops at the FIRST True condition. Everything after — even a technically-true elif — is never even evaluated.
↓
WHYif/elif/elif/else is one single decision, not several independent ifs. Order therefore matters — put the most specific condition first.
🔮 PREDICTION MODE — WHAT WILL PYTHON PRINT?
score = 75

    print("A")
elif score >= 70:
    print("B")

    print("C")

What gets printed?
75 ≥ 90 is False, so Python checks the next one: 75 ≥ 70 is True → prints "B" and stops. It never even looks at the ≥60 check, even though 75 ≥ 60 is also true.
ALSO IN THE SOURCE If you're comparing one value against several literal constants (rather than ranges like >= 70), the match statement is often a cleaner fit than a long elif chain — covered next.
4.7

match Statements

Moved up next to if because it solves the same problem — "compare one value against several possibilities" — just with more power: it can also unpack and bind.

SIMPLE MODEL Think of match as an evolved elif-chain that can also say "and while you're at it, pull these pieces out into variables." Python compares the subject to each case pattern top to bottom, and runs the first one that fits — exactly like if/elif.
TECHNICAL The wildcard case _: never fails to match — it's the "else" of a match statement. If no case matches and there's no _, nothing executes.

Level 1 — literal matching (the switch-statement-like form):

def http_error(status):
    match status:
        case 400:
            return "Bad request"
        case 404:
            return "Not found"
        case 401 | 403 | 404:   # "|" means OR
            return "Not allowed"
        case _:
            return "Something's wrong with the internet"

Level 2 — patterns that bind variables. This is what makes match different from a plain switch: a bare name in a pattern captures whatever value sits in that position.

# point is an (x, y) tuple
match point:
    case (0, 0):
        print("Origin")
    case (0, y):
        print(f"Y={y}")      # y is BOUND from point
    case (x, 0):
        print(f"X={x}")
    case (x, y):
        print(f"X={x}, Y={y}")
    case _:
        raise ValueError("Not a point")

Read a pattern the way you'd read the left side of an assignment: (0, y) means "first slot must literally be 0; whatever is in the second slot, call it y." Only bare names like y get assigned — dotted names, keyword names, and class names in a pattern are never assignment targets, they're comparisons.

DECISION VISUALIZER — how point=(0, 5) resolves

Level 3 — matching class instances, extracting attributes into variables:

class Point:
    __match_args__ = ('x', 'y')
    def __init__(self, x, y):
        self.x = x
        self.y = y

def where_is(point):
    match point:
        case Point(x=0, y=0):
            print("Origin")
        case Point(x=0, y=y):
            print(f"Y={y}")
        case Point() if point.x == point.y:   # a GUARD
            print("On the diagonal")
        case Point():
            print("Somewhere else")
        case _:
            print("Not a point")

The if after a pattern is a guard: the pattern must match first (and its captures happen first), then the guard is checked. If the guard is False, match moves on to the next case — it does not stop trying.

⚠ COMMON TRAP
BEGINNERS THINK"case Color.RED matches by capturing a variable named RED, like case (x, y) captures x and y."
↓
PYTHON ACTUALLY DOESA DOTTED name (Color.RED) is a value comparison, never a capture. Only bare names (RED with no dot) capture.
↓
WHYThis is intentional: if bare "RED" appeared in a case, it WOULD capture — meaning it'd match anything and silently shadow the real check. The dot is what tells match "compare against this constant."
🔮 PREDICTION MODE — WHAT WILL PYTHON PRINT?
command = ["go", "north"]
match command:
    case ["go", direction]:
        print(f"Going {direction}")
    case ["look"]:
        print("Looking around")
    case _:
        print("Unknown command")
What gets printed?
["go", "north"] has 2 elements. The pattern ["go", direction] requires the first element to literally equal "go" (it does) and binds the second element to direction — so direction = "north", printing "Going north".
4.2

for Statements

If you learned C or Pascal's for-loop first, unlearn it here. Python's for doesn't count — it walks through items.

SIMPLE MODEL A Python for loop is a conveyor belt: it pulls items off a sequence one at a time, in order, and hands each one to your loop variable — until the sequence runs out. It is never about counting from 0 to N; that's just one possible thing you can put on the belt.
TECHNICAL for w in words iterates over the items of any sequence (list, string, etc.) in order — unlike C's index-and-condition style loop.
EXECUTION VISUALIZER 
words = ['cat', 'window', 'defenestrate']for w in words:    print(w, len(w))
VARIABLES
OUTPUT
WHAT'S HAPPENING
MODIFYING WHILE ITERATING Deleting or adding items to a collection while looping over that same collection is a classic source of skipped items or crashes. The fix: loop over a copy, or build a new collection instead.
✗ RISKY — mutating while iterating 
for user, status in users.items():
    if status == 'inactive':
        del users[user]  # RuntimeError!
✓ SAFE — iterate over a copy 
for user, status in users.copy().items():
    if status == 'inactive':
        del users[user]  # fine

Or avoid mutation entirely by building a fresh dict: active_users = {u:s for u,s in users.items() if s=='active'} — arguably the cleanest option of all.

🔮 PREDICTION MODE — WHAT WILL PYTHON PRINT?
for ch in "abc":
    print(ch.upper())
What gets printed?
Strings ARE sequences in Python, so for ch in "abc" walks through each character. Each print() call ends with a newline by default, so A, B, C land on separate lines.
4.3

The range() Function

Need numbers to iterate over? range() generates them on demand — without ever building the full list in memory.

SIMPLE MODEL range(a, b, step) is a recipe for numbers, not a box of numbers. Python only computes the next number when you actually ask for it — that's why print(range(10)) shows range(0, 10) instead of a list.
TECHNICAL range() returns an iterable — an object that produces successive items on demand — which is memory-efficient for huge ranges.
INTERACTIVE — DRAG THE SLIDERS, WATCH THE SEQUENCE

⚠ COMMON TRAP
BEGINNERS THINK"range(5, 10) includes 10, since 10 is the endpoint I typed."
↓
PYTHON ACTUALLY DOESThe stop value is NEVER included. range(5, 10) → 5, 6, 7, 8, 9. Five numbers, matching len() = 5.
↓
WHYThis "half-open" design makes range(len(a)) automatically produce exactly the legal indices of a — no off-by-one needed.

Iterating over indices: combine range() with len() — but prefer enumerate() when you also need the value:

a = ['Mary', 'had', 'a', 'little', 'lamb']

# Works, but verbose:
for i in range(len(a)):
    print(i, a[i])

# Usually preferred:
for i, word in enumerate(a):
    print(i, word)
🔮 PREDICTION MODE — WHAT WILL PYTHON PRINT?
print(sum(range(4)))
What gets printed?
range(4) generates 0, 1, 2, 3 (4 is excluded). sum() is a function that accepts any iterable, so it adds them: 0+1+2+3 = 6.
4.4

break and continue Statements

Two exits from the normal flow of a loop: one leaves entirely, the other just skips ahead.

SIMPLE MODEL break = "leave the building now, don't finish this floor or any floor after it."
continue = "skip the rest of this floor, but go check the next floor as normal."
TECHNICAL break exits the innermost enclosing for/while loop entirely. continue jumps straight to the next iteration.
break — finding the first factor of each number 
for n in range(2, 5):    for x in range(2, n):        if n % x == 0:            print(f"{n} = {x} * {n//x}")            break
VARIABLES
OUTPUT
WHAT'S HAPPENING
SCOPE OF BREAK break only escapes the innermost loop it's inside. In the visualizer above, break exits the x loop — the outer n loop calmly continues to n=5.
break — leaves the loop

        break

# the FIRST number checked and is even)
continue — skips ahead 
for num in range(2, 6):
    if num % 2 == 0:
        continue
    print(num)

#         5
# (loop keeps running, just skips evens)
⚠ COMMON TRAP
BEGINNERS THINK"continue skips to the next LINE, like a goto."
↓
PYTHON ACTUALLY DOEScontinue skips to the next ITERATION — jumping straight back to the loop's condition check, not the next line of code in sequence.
↓
WHYAny code left in the loop body AFTER continue on that pass is skipped entirely, not just the current statement.
🔮 PREDICTION MODE — WHAT WILL PYTHON PRINT?
for i in range(5):
    if i == 3:
        break
    if i == 1:
        continue
    print(i)
What gets printed (in order)?
i=0: not 3, not 1 → print 0. i=1: not 3, IS 1 → continue, skip print. i=2: not 3, not 1 → print 2. i=3: IS 3 → break, loop ends entirely. Result: 0, 2.
4.5

else Clauses on Loops

The single most misunderstood keyword pairing in Python. It has almost nothing to do with if/else.

SIMPLE MODEL Rename it in your head to nobreak. A loop's else runs only if the loop finished naturally — completed all its iterations, or its while-condition went False — without ever hitting a break.
TECHNICAL The else clause is skipped if the loop ends via break, return, or a raised exception — it behaves like a try statement's else (runs when nothing interrupted the flow), not like an if's else.
prime check — for/else in action 
for n in [4, 5]:    for x in range(2, n):        if n % x == 0:            print(n, 'equals', x, '*', n//x)            break    else:        print(n, 'is a prime number')
VARIABLES
OUTPUT
WHAT'S HAPPENING
READING TIP FROM THE SOURCE Mentally pair the else with the if inside the loop — as the loop runs, it behaves like a sequence of if/if/if/else. Every time the if is True, break fires. If the if is never True across the whole loop, the else outside finally runs.
⚠ COMMON TRAP
BEGINNERS THINK"else belongs to the if statement right above it inside the loop."
↓
PYTHON ACTUALLY DOESLook at the INDENTATION: the else lines up with 'for', not with 'if'. It belongs to the loop, not the inner if.
↓
WHYThis is exactly the example the Python docs call out: "Look closely: the else clause belongs to the for loop, not the if statement."
🔮 PREDICTION MODE — WHAT WILL PYTHON PRINT?
for i in range(3):
    print("checking", i)
else:
    print("loop finished cleanly")
What gets printed?
There's no break anywhere, so the loop simply runs to completion — which counts as finishing "without a break." The else clause always runs unless a break interrupted it; no break needs to be present in the loop for else to be legal or to fire.
4.6

pass Statements

The shortest statement in Python. It does precisely nothing — which is exactly the point.

SIMPLE MODEL Python's grammar sometimes demands a body ("something must go here"), but you have nothing to say yet. pass is a placeholder that satisfies the syntax while doing zero work at runtime.
TECHNICAL Commonly used for stub functions, empty classes, and busy-wait loops during development.
Empty class placeholder 
class MyEmptyClass:
    pass
Unfinished function placeholder 
def initlog(*args):
    pass   # TODO: implement
pass vs ... Many developers use the ellipsis literal ... in place of pass as a placeholder body. It has no special meaning to the language (any constant expression would technically work) — it's purely a convention, not a rule.
4.8

Defining Functions

Every function you define secretly returns something — even the ones that "just print stuff."

SIMPLE MODEL Every function call opens a fresh, private notebook (its local symbol table). Anything the function assigns gets written in THAT notebook, not the caller's. When the function ends, the notebook is thrown away — unless you hand something back with return.
TECHNICAL Variable references look up the chain: local → enclosing function(s) → global → built-ins. Variable assignment, however, always writes to local — unless declared global or nonlocal.
fib2() — building and returning a list 
def fib2(n):    result = []    a, b = 0, 1    while a < n:        result.append(a)        a, b = b, a+b    return resultf = fib2(8)

WHAT'S HAPPENING
⚠ COMMON TRAP
BEGINNERS THINK"A function with no return statement, like one that only calls print(), returns nothing at all."
↓
PYTHON ACTUALLY DOESIt always returns something: None. "Falling off the end" of a function is exactly the same as writing "return None".
↓
WHYprint(fib(0)) explicitly shows None printed — the interpreter just normally hides a bare None result at the prompt, which is why beginners never notice it.
🔮 PREDICTION MODE — WHAT WILL PYTHON PRINT?
def greet(name):
    message = f"Hello, {name}"

print(result)
What gets printed?
greet() builds the string but never returns it — it just assigns it to a LOCAL variable that vanishes when the function ends. Falling off the end returns None, so result = None, and print(result) shows "None".
4.9.1

Default Argument Values

The most famous gotcha in all of Python starts here. Read this one twice.

SIMPLE MODEL A default value is computed once, at the moment Python reads the def line — not fresh on every call. Think of it as a sticky note pinned to the function's definition, written a single time.
TECHNICAL Default values are evaluated in the defining scope at function-definition time, and that same object is reused for every call that doesn't override it.
i = 5
def f(arg=i):
    print(arg)
i = 6
f()   # prints 5, NOT 6 — the default was locked in when def ran
INTERACTIVE — THE MUTABLE DEFAULT TRAP, LIVE
def f(a, L=[]):
    L.append(a)
    return L
Using L=[] (shared mutable default)
CLICK TO CALL f(1), THEN f(2), THEN f(3):
⚠ COMMON TRAP
BEGINNERS THINK"L=[] gives me a fresh empty list every time f() is called, just like inside the function body."
↓
PYTHON ACTUALLY DOESThe SAME list object is reused across every call that relies on the default — appends from call 1 are still there in call 2.
↓
WHY / FIXUse L=None as the default, then inside the function: "if L is None: L = []" — this creates a genuinely new list on every call.
🔮 PREDICTION MODE — WHAT WILL PYTHON PRINT?
def f(a, L=None):
    if L is None:
        L = []
    L.append(a)
    return L

print(f(1))
print(f(2))
What gets printed?
Because the default is None (immutable, and just a signal), each call that doesn't pass L creates a genuinely NEW empty list via "L = []" inside the function body. Nothing is shared between calls anymore.
4.9.2

Keyword Arguments

Calling by name instead of position. Great for readability — but it has strict rules about ordering and duplicates.

SIMPLE MODEL Positional args are "the first box, then the second box, then the third." Keyword args are "the box labeled voltage, wherever it goes." You can mix both — but once you start labeling boxes, every box after must also be labeled.
TECHNICAL In a call, keyword arguments must come after positional arguments. No argument may receive a value more than once — mixing a positional and keyword value for the same parameter is a TypeError.
def parrot(voltage, state='a stiff', action='voom', type='Norwegian Blue'):
    print(f"Wouldn't {action} at {voltage} volts. {state}. {type}.")

parrot(1000)                                    # ✓ 1 positional
parrot(voltage=1000)                            # ✓ 1 keyword
parrot(action='VOOOOOM', voltage=1000000)       # ✓ keyword order doesn't matter
parrot('a million', 'bereft of life', 'jump')   # ✓ 3 positional
INTERACTIVE — VALID OR INVALID CALL?

Given def parrot(voltage, state='a stiff', action='voom', type='Norwegian Blue'), click each call to check it.

⚠ COMMON TRAP
BEGINNERS THINK"function(0, a=0) should work — Python will just figure out I mean the same thing twice, or override it."
↓
PYTHON ACTUALLY DOESTypeError: got multiple values for argument 'a'. The positional 0 already filled parameter a; the keyword a=0 tries to fill it AGAIN.
↓
WHYPython resolves positional arguments to parameter slots first, then keyword arguments. A collision on the same slot is always an error, never a silent overwrite.
🔮 PREDICTION MODE — VALID OR ERROR?
def parrot(voltage, state='a stiff', action='voom'):
    pass

parrot(110, voltage=220)
What happens?
110 is a positional argument, so it fills voltage first. Then voltage=220 tries to fill the SAME parameter again by keyword. Same trap as function(0, a=0) — always a TypeError.
4.9.3

Special Parameters — / and *

Three zones in a function signature, controlled by two punctuation marks. This is the section interviewers love to probe.

SIMPLE MODEL Read a signature left to right as three rooms separated by doors: everything before / can ONLY be reached by position (name doesn't matter — like arguments to len()). Everything after * can ONLY be reached by name. The middle room, with no doors around it, accepts either.
TECHNICAL def f(pos1, pos2, /, pos_or_kwd, *, kwd1, kwd2) — both / and * are optional and independent of each other.
FLOW VISUALIZER — the three zones of a signature
INTERACTIVE — TEST A CALL AGAINST THE SIGNATURE
def combined_example(pos_only, /, standard, *, kwd_only):
    print(pos_only, standard, kwd_only)
RESULT
Click a call above to test it against the signature.
WHY USE THESE AT ALL? Positional-only: hides parameter names from the caller — useful when names are meaningless, or to freely rename them later without breaking an API. Keyword-only: forces clarity when the argument's meaning isn't obvious from position alone.
🔮 PREDICTION MODE — VALID OR ERROR?
def pos_only_arg(arg, /):
    print(arg)

pos_only_arg(arg=1)
What happens?
The trailing / makes arg positional-only — its name is not part of the public calling interface at all. Calling with arg=1 is a TypeError, even though arg is the correct parameter name.

Arbitrary Argument Lists — *args, **kwargs

When you don't know in advance how many arguments will show up.

SIMPLE MODEL *args is a bag that catches every leftover positional argument, as a tuple. **kwargs is a bag that catches every leftover keyword argument, as a dictionary. Order in the signature matters: named params, then *args, then **kwargs.

4.9.5

Unpacking Argument Lists

The reverse of *args/**kwargs: you already have a list or dict, and need to blow it apart into separate arguments.

SIMPLE MODEL * and ** at a CALL site do the opposite of what they do at a definition site: instead of gathering loose arguments into a container, they spill a container's contents out as separate arguments.
Packing (at definition) 
def f(*args, **kwargs):
    ...
# loose args → gathered into
# a tuple / dict
Unpacking (at call site) 
args = [3, 6]
list(range(*args))
# a list/dict → spilled into
# separate arguments
d = {"voltage": "four million", "state": "bleedin' demised", "action": "VOOM"}
parrot(**d)
# equivalent to:
# parrot(voltage="four million", state="bleedin' demised", action="VOOM")
🔮 PREDICTION MODE — WHAT WILL PYTHON PRINT?
args = [3, 6]
print(list(range(*args)))
What gets printed?
*args unpacks the list [3, 6] into two separate positional arguments — exactly like calling range(3, 6). That generates 3, 4, 5 (6 excluded, as always).
4.9.6

Lambda Expressions

A function so small it doesn't get a name — or a def, or a return keyword.

SIMPLE MODEL lambda a, b: a + b is exactly the same thing as def f(a, b): return a + b — just squeezed onto one line, with the return implied and no name required. It's syntactic sugar, nothing more.
TECHNICAL Lambdas are restricted to a single expression (no statements, no multiple lines) and can capture variables from the enclosing scope, just like nested def functions.
Normal function 
def make_incrementor(n):
    def inner(x):
        return x + n
    return inner

f = make_incrementor(42)
f(0)   # 42
Same thing, as a lambda 
def make_incrementor(n):
    return lambda x: x + n

f = make_incrementor(42)
f(0)   # 42
INTERACTIVE — SORT WITH A LAMBDA KEY
pairs = [(1, 'one'), (2, 'two'), (3, 'three'), (4, 'four')]
pairs.sort(key=lambda pair: pair[1])
Sort by pair[1] (the word) instead of pair[0] (the number)
RESULT
🔮 PREDICTION MODE — WHAT WILL PYTHON PRINT?
square = lambda x: x * x
print(square(5))
What gets printed?
square is just a name bound to the lambda function object, exactly like any def'd function. Calling square(5) evaluates x*x with x=5, giving 25.
4.9.7 / 4.10

Docstrings & Coding Style (PEP 8)

Not exciting. Extremely interview-relevant. Skimmed by beginners, tested by interviewers.

Docstring conventions:

  • First line: a short, capitalized summary ending with a period — don't restate the function's name.
  • If there's more, leave a blank line after the summary before further paragraphs.
  • Access it anytime via function.__doc__.
def my_function():
    """Do nothing, but document it.

    No, really, it doesn't do anything.
    """
    pass

print(my_function.__doc__)
# Do nothing, but document it.
#
#     No, really, it doesn't do anything.

PEP 8, the essentials an interviewer expects you to just know:

RuleDetail
Indentation4 spaces, never tabs.
Line lengthWrap before 79 characters.
Blank linesSeparate functions/classes and major blocks.
SpacingSpaces around operators and after commas — but not just inside brackets: f(1, 2) + g(3, 4).
NamingUpperCamelCase for classes, lowercase_with_underscores for functions/methods.
selfAlways the name of a method's first argument.
EncodingUse UTF-8 (Python's default); avoid non-ASCII identifiers for shared/international code.

ANSWER No — PEP 8 wants a space after each comma: f(1, 2) + g(3, 4). Spacing after commas (but not directly inside brackets) is one of the most commonly checked style rules.

LEVEL 3 · CONCEPT
Explain WHY range(10) printed on its own shows range(0, 10) instead of the list [0, 1, ..., 9].
ANSWER range() doesn't build the list — it returns an iterable object that computes each number on demand as something iterates over it. This is why it's memory-efficient for huge ranges: range(10**9) takes almost no memory, while list(range(10**9)) would try to materialize a billion integers.
LEVEL 4 · DEBUGGING
Find the bug. This function is meant to collect a running log across separate calls, but instead one caller's data leaks into another's: 
def add_entry(entry, log=[]):
    log.append(entry)
    return log

user_a_log = add_entry("login")
user_b_log = add_entry("logout")
print(user_b_log)  # BUG: shows ['login', 'logout'], not just ['logout']
ANSWER The mutable default log=[] is the classic trap: it's created once and shared across every call that doesn't supply its own log. Fix: def add_entry(entry, log=None): if log is None: log = [] — this gives every call that needs a default a genuinely fresh list.
LEVEL 4 · DEBUGGING
Find the bug — this is supposed to print all users, skipping inactive ones, but crashes or silently skips entries: 
users = {'a': 'active', 'b': 'inactive', 'c': 'active'}
for user, status in users.items():
    if status == 'inactive':
        del users[user]
ANSWER Deleting from a dict while iterating over that same dict raises a RuntimeError (dictionary changed size during iteration). Fix: iterate over users.copy().items(), or build a new dict of only the active users instead of mutating in place.
LEVEL 5 · INTERVIEW TRAP
An interviewer shows you this and asks what it prints. There's a subtle misconception baked into the "obvious" wrong answer — what is it? 
i = 5
def show(x=i):
    print(x)
i = 99
show()
ANSWER Prints 5, not 99. The misconception is assuming default values are re-evaluated at CALL time, looking up whatever i currently is. In reality, x=i is evaluated once, when the def statement runs — i was 5 at that moment, and that value is locked into the default forever, independent of i's later reassignment.
LEVEL 5 · INTERVIEW TRAP
What does this print, and why do most people guess wrong on the first read? 
for n in range(2, 4):
    print(n, "start")
else:
    print("done")
ANSWER Prints: "2 start", "3 start", "done". Most people guess the else is dead code or a syntax error because there's no break or if anywhere near it. But a loop's else only cares about ONE thing — did a break happen? Since this loop has no break at all, it always finishes "cleanly," so else unconditionally runs.
